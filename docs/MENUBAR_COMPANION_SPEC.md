# BitRouter 菜单栏伴侣 MVP

状态：**MVP v0.5，菜单栏信号与 managed agent lifecycle 已实现供 review；最终验收记录见独立 UI 仓库。**
日期：2026-09-19。已有能力核对基线：`2b01d2e6`。
暂定名称：**BitRouter Bar**。本文替代 v0.1 的首版范围。

## 1. 要验证的价值

用户已经安装并使用 BitRouter，再安装一个常驻菜单栏的小 App，便能随手看到：
**各客户端今天用了多少 tokens、展开后各会话用了多少、相关账户还剩多少额度，
以及 managed agent 当前在做什么、是否需要人处理。**

MVP 验证用户是否愿意为了这个小窗长期保留 App。第一版只有一个固定菜单栏图标
和一个弹出面板。默认按客户端汇总，展开看会话；不继续进入详情页面。

**已确认：UI 子项目使用独立 Git 仓库，独立构建和发布，不放在 BitRouter 仓库内。**

## 2. 唯一主界面

以下名称和数字均为示意，不代表额度来源已接通：

```text
BitRouter

▾ Codex                              今日 160k
  账户 A：剩余 42% · 2h 后恢复
    会话 a81f                            128k
    会话 b92e                             32k

▸ Claude Code                         今日 86k
  账户 B：剩余 67% · 4h 后恢复

更新于 30 秒前                        刷新 · 退出
```

- 点击菜单栏图标打开面板，点击外部关闭；关闭面板或退出 App 都不停止 BitRouter。
- 显示今天有记录的客户端，按今日 tokens 降序排列；无记录时显示“今日暂无记录”。
- 点击客户端展开/收起根会话，按最近活动排序；每行只有会话短 ID 和今日 tokens。
- 子 agent 用量计入有可靠关联的根会话，首版不展示子线程树。
- 额度直接显示在相关客户端下方；多个账户分别列出，共用账户标记“共享额度”。
- 同一账户存在多个限制窗口时，用简短、带窗口名称的行分别显示，不增加窗口选择器。
- 内容多时在面板内滚动。若读取达到限额，明确提示并提供继续加载，不能静默遗漏；
  客户端总计始终覆盖全部相关记录，不能由当前可见会话相加冒充。
- 服务未启动、读取失败、版本不支持时显示直接可理解的提示；旧数据保留并标记过期。
- 保留原生基本键盘操作与辅助功能标签；状态同时有文字，不只依赖颜色。

## 3. 首版明确不做

- 固定客户端、自定义排序和任意用户公式；菜单栏只提供已定义的 usage/quota 显示模式。
- 趋势图、日期切换、会话累计、会话详情、模型/provider 分布。
- 费用、缓存和推理 token 明细、请求列表、子线程树。
- 聊天、agent 启动、配置编辑、路由修改、reload、daemon 进程管理。
- 多实例选择、远程连接、跨机器汇总、独立管理窗口。
- 客户端日志扫描、绕过 BitRouter 的请求统计、登录时启动设置。通知仅用于 managed lifecycle
  的审批、完成、失败和断开事件，并由用户主动开启。
- 通用额度插件体系、多个专用查询 API、独立账户管理平台。

## 4. 必须准确的几个口径

### 用量

只统计经过 BitRouter 且已结算记录的请求，不承诺生成过程中的实时 token 计数。
“今日”按 App 本地自然日计算，向读取层传入明确时间边界，正确处理午夜和夏令时。

复用现有 token 归一化逻辑：输入中的缓存、输出中的 reasoning 不重复相加。
未知用量不当成零，估算用量要标明；有未知请求时显示“部分用量未知”。
同一请求只计一次，结算修正不能成为新增消耗。统计范围受现有计量证据覆盖限制，
不宣称记录了未被计量的上游重试。

### 客户端与会话

复用现有身份归属。无法识别客户端的请求进入“未识别客户端”；已知客户端但
缺少会话身份时进入“未归属会话”。不能根据模型名猜测客户端。

相同裸会话 ID 在不同调用方或 controller/来源命名空间下不能直接合并。
每条请求只进入一个客户端、一个根会话或未归属分组；子会话不重复累计。
无需为 MVP 重建身份体系，但现有证据不足时必须保留未知状态。

### 额度

额度属于实际使用的上游账户，不属于客户端本身。账户关联必须有实际凭据选择
证据；provider 名称、入站 API key 和客户端名称都不能代替账户身份。

同账户在不同客户端下共享额度，不能相加；不同账户或窗口也不能合并为一个余额。
用量是经 BitRouter 的记录，账户额度可能还包含其他机器或客户端的消耗。

上游给百分比就显示百分比，不擅自换算成 token 数。没有恢复时间就不显示倒计时；
滚动恢复不能冒充固定重置。上下文长度、配置的限速值都不是订阅剩余额度。

不支持查询时显示“暂不支持额度查询”；已支持但失败时显示刷新失败及旧值时间。
账户映射未知时显示“账户未知”，不挂上其他账户的额度。解绑后不继续显示旧余额。

## 5. 最小实现边界

首版使用 macOS 14+、SwiftUI/AppKit。App 独立安装，连接一个本地 BitRouter。
独立仓库名为 `bitrouter-bar`，拥有自己的 UI 源码、构建配置、安装包和 release。
BitRouter 主仓库只补必要的数据读取能力，不引入 UI 源码或 Swift 构建依赖。
独立 Git 仓库已创建为 `bitrouter-bar`；本仓库只包含读取接口和这份跨仓库契约。

App 通过本地读取契约连接已安装的 BitRouter，不直接链接主仓库内部 Rust 类型。
各自独立发版。当前兼容门槛为 `bro panel` 的 `schema_version: 1`；包含该命令的
正式版本发布后再标明最低版本号。旧版提示升级，不要求两个仓库绑定同一个 commit。
后续 UI spec 随独立仓库维护，本文件保留跨仓库契约。

App 只负责显示和原生菜单交互。BitRouter 侧提供**一个面板读取结果**，包含今日
客户端汇总、会话行、关联账户额度、managed ACP lifecycle snapshot、短时可通知事件日志
和各部分更新时间/错误状态。后续大量会话所需的有界加载继续使用这一个读取能力。
仅经过路由的客户端没有完成/审批语义，保留最近活动或未知状态，不能由请求沉默推断。
Managed lifecycle 的 `updated_at` 表示可见状态/活动发生变化的时间；10 秒 heartbeat
只延长 snapshot 存活期，不重写该时间。对于 routed `bro code`，ACP 返回 `end_turn`
时还会按同一 principal/controller/session 和本轮起始时间核对 settled request：仅当
本轮至少一条请求且全部失败时改报 `failed`；证据不可用、无请求或存在成功请求时
不臆测失败。direct session 继续以 ACP outcome 为准。

用量在服务端按完整记录聚合，不能对现有 `/requests` 的最近 500 条做求和来
生成总量。每次刷新整体替换面板用量，避免客户端自行累计；额度保留独立采样时间。

连接方式已确定为 **`bro panel` → 现有本地 owner IPC**，复用本地权限边界。
App 传入 `--since`、`--until`、`--session-limit`、`--session-offset`，读取版本化 JSON。
继续加载保持相同时间边界并使用不可变快照；快照过期时提示重新刷新。
安装后连接默认本地实例，不要求用户另配管理端口、control token 或账户。
如现有路径无法做到，先回报具体缺口，不静默改配置或绕过认证。

不直接从 UI 打开数据库、不复制 OAuth 刷新逻辑，也不让 UI 获取 provider 密钥。
额度查询及缓存放在 BitRouter 侧，只为已验证来源实现需要的适配代码。
同账户查询去重，失败退避，手动刷新不突破上游限频；额度失败不影响推理。

App 以轻量后台读取保持菜单栏数字和 lifecycle 通知；菜单打开时也继续刷新。
重新打开时先显示带时间的缓存。额度读取仍受缓存有效期和上游限频约束；后台读取
不会绕过 Codex 额度缓存 60 秒与失败退避。通知默认关闭，由用户在原生菜单中开启。
展开分页后暂停自动替换，保留已加载会话；手动刷新、重新打开或跨自然日时恢复。
不引入首版可调参数。

已实现完整时间范围的客户端/根会话聚合，以及基于实际凭据选择证据的匿名账户关联。
历史记录缺少账户证据时保留未知，不通过当前登录状态补写历史归属。

用户已确认首轮以当前 Codex 账户验收，Claude 明确显示不可用。
实际 Codex 请求已经经过 BitRouter 完成，计量记录和面板一致为 16,864 tokens；
同一凭据来源的额度查询返回 HTTP 200 和每周百分比窗口。Claude 本地登录凭据
不可用，首版没有宣称接通 Claude 额度。不设计通用 provider 扩展框架。

所有已记录客户端都可展示用量；没有额度来源的行明确不可查询。

## 7. 四条验收条件

1. **看到客户端用量**：打开面板，今天各客户端 tokens 与完整计量记录一致；
   大于 500 条请求仍准确，缺失身份或用量不会被悄悄丢掉或补零。
2. **展开看到会话**：客户端下的今日会话归属正确，子 agent 不重复计算；
   相同裸 ID 不串组，跨午夜后仍符合今日口径。
3. **看到真实额度**：用户实际使用的主要账户完成真实查询核对；共享、未知、
   不支持和过期状态表达正确，多账户/窗口不混算。假数据演示不算通过。
4. **能长期常驻**：安装后能读取本地 BitRouter，服务未启动有提示；面板开关、
   休眠恢复和退出不干扰 daemon，不频繁查询上游，不泄露凭据或会话正文。

针对这些条件验证聚合、归属、额度失败状态及原生面板实际体验即可，不为未来
功能建设测试平台。涉及 Rust 源码时仍需完成仓库规定的检查。常驻表现须实际测量，
不以“原生”替代低占用证据。

## 8. 执行顺序

1. 核对用户主要账户的真实额度来源、请求到上游账户的映射，以及最小本地读取路径。
2. 在 BitRouter 侧补足一个面板读取能力，正确聚合客户端与会话，关联已验证额度。
3. 在独立 `bitrouter-bar` 仓库实现固定图标与单面板，用真实请求和账户走通四条
   验收，再由该仓库打包、发布 App。

本次实现新增 `bro panel`，已同步 `skills/bitrouter/`、CLI 文档和适用插件清单。
独立 App 的构建、打包及验收记录在 `bitrouter-bar` 仓库维护；当前是本地候选包，
公开发布、Developer ID 签名和 notarization 尚未完成。

产品形态参考：[TokenBar](https://github.com/Nanako0129/TokenBar)。

## 9. 原生菜单修订（UI 仓库）

用户 review 后确认使用原生菜单和会话子菜单，替代固定高度弹出面板及内联展开。
具体交互以独立 `bitrouter-bar` 仓库的 `docs/MVP.md` 为准；读取契约保持 schema v1。
菜单关闭可取消正在进行的读取；daemon 已隔离单个 IPC 连接的断开/写回复失败，
避免正常 UI 取消使路由服务退出。主动 Stop 即使调用方断开也仍生效。
