## Material and authority

The private artifact retains the original typed permission snapshot fields. Separate context records the run, permission, canonical original-request SHA-256, event sequence cutoff and earlier declarations for the same tool. It retains declared kind, locations, input and status, omitting output/content from the supplementary declarations. It does not overwrite the original request or prove tool execution. Restoring and serializing the original snapshot yields identical canonical bytes.

Supplementary context requires complete, contiguous history and a unique matching original permission. It is bounded to 32 declarations and 64 KiB. Missing/omitted/oversized history disables automatic local approval rather than dropping conflicting context and relying on residual fields. Conflicting kind/input, reused calls, prior terminal events and later scope/argument changes also disable automatic approval. Earlier paths accumulate; a later local path cannot hide an earlier external path.

Existing local policy still only chooses an actual offered nonpersistent option for declared read/edit/search inside the canonical owned workspace. Parent traversal, external symlinks, protected edit paths, terminal execution and network actions are not granted by this policy. Before controller selection, the coordinator rereads the current request/history and compares it with saved material. Controller selection acknowledgement remains separate from protocol transmission and tool effects. This reread is not an operating-system sandbox or proof that a harness cannot perform undisclosed work.

The preview labels earlier declarations separately, keeps the original request visible and reports conflicting or unavailable context. Model input receives both sources as untrusted observations. Existing recovery matching compares the original canonical snapshot rather than treating supplementary metadata as new original request fields.
