## 决定

| ID | 选择与依据 |
| --- | --- |
| D01 | 在 `bitrouter-orchestrator::goal` 增加 Goal 领域合同与服务，在 app 中增加同一 SeaORM 数据库的事务实现；不重命名旧 Thread，不使用 trace extractor 作为状态权威。当前 `agent_store.rs` 和 `db/migration` 提供提交/CAS 模式 |
| D02 | 复用 owner-only 本地 daemon IPC，装配一个 Goal 服务供查询/提交使用。不会新增公开 HTTP Goal API，remote inspection 的读权限不升级为执行权限 |
| D03 | 按最小切片添加实际消费的字段与操作。S1 先提供持久接收、要求版本、运行意图、冷查询与操作去重；未产生执行时不能报告运行或已采用 |
| D04 | 保留 native ThreadService、ACP supervisor 与 harness session 各自的身份/权威；新 Goal 统一协调上层任务，不建立第二份 private harness transcript 或 provider 客户端 |
| D05 | app 将权威数据转换为 TUI 自有展示类型，renderer 保持同步；默认入口切换安排在 S6，避免以 UI 替换冒充执行闭环 |
| D06 | typed backend 复用已经装配的 `App::decision_model()` 和现有 `decision_model:` 配置，初始接入 TypeSafe typed executor；没有配置时保留推理备用与明确状态，不复制 auth 客户端。真实调用与输入质量仍待 S3/S7 验证 |
| D07 | 新 Goal IPC 使用独立 protocol，S1 为 v1；D43 的 Create 初始预算改变 command/fingerprint 形状后升至 v2。旧 native local v17/HTTP v2 不改。local transport 决定 owner，request 不允许自行声明 owner；remote inspection 没有 Goals 操作。旧 Goal protocol/outbox 明确拒绝，不改写旧 payload 或据此重放 |
| D08 | 接收层仅记录原始输入，不按问号/关键词直接修改目标。控制意图持久提交与实际执行停止保持分离；未执行工作不报告正在运行或已经采用 |
| D09 | Goal 内任务图拒绝重复身份、失效依赖、环路与不可用 harness。计划提议、执行尝试、supervisor run 和 harness session 各自保留身份；独立分支由同一 daemon 服务协调，UI 不启动 worker |
| D10 | 每个 Goal 使用持久 coordinator lease 和 CAS；lease 为 30 秒、到期前续约。提交及 ACP 启动前核对当前 owner；过期或不同 owner 不能提交新的执行事实。多实例、时钟与失败续约仍需实际验证 |
| D11 | 规划复用 SDK 的实际路由管线；先记录 planning attempt，再调用模型。S4 已切换为 `App::execute_native_controlled`，每次实际回退 attempt 都经同一持久 gate。daemon 重启后没有确认结果的 attempt 不重新收费调用。已接入 elapsed 与已知 token 估算 gate；完整费用合同仍待补齐，不声称已有全 Goal 金额硬上限 |
| D12 | 初始隔离采用不同 Git worktree，复制当前 tracked binary diff 和有界非忽略普通文件；保留交付工作区。当前仅支持 repository root，非 Git / subdirectory 映射与稳定输入版本仍待补齐。worktree 不是 OS sandbox，permission 默认 Ask，不用标题匹配替代硬授权边界 |
| D13 | 调度记录先提交再创建 worktree / 调用同一 ACP supervisor；使用 Start/Peek/Transcript/Stop 的内部 exact-scope grant，不把 Goal ID 写成 parent run ID。权限路径实际消费后增加 Respond；启动映射缺失和中断窗口不自动重放 |
| D14 | 候选输出与停止事实分别持久记录；暂停后停止已有候选的所属进程也不会删除结果。仅实际 `Stopped` 快照支持 owned process stop confirmation，外部效果仍需协调，不能据此提交 Goal 完成 |
| D15 | 后台推进与 owner 续约接入原 handoff admission gate；分页待调度队列保留当前位置，避免只服务前八个 Goal。app build fingerprint 增加 Goal runtime/store；协议、包装和真实 handoff 回归仍待检查 |
| D16 | 候选报告和 workspace bundle 使用 Goal 私有目录的 SHA-256/长度引用；读取重新检查身份、实际内容和归属。单个 blob 64 MiB，workspace 总量 256 MiB、文件数 4096；模型评审材料另有 512 KiB 限制，二进制材料需要可处理的评审路径，不能假装通过 |
| D17 | 分支交接先确认 owned process 停止，再捕获实际材料并记录 review attempt；复用 SDK 推理路由，保存其真实 request ID 和 verdict 引用。评审后再次捕获，内容改变、条件版本变化或未支持的检查都不能批准。语义交接不是机器检查，也不是 Goal 完成判定 |
| D18 | 新工作区创建私有基线 commit；不提交用户原 checkout。依赖转移采用 Git 三方合并/index，支持共同上游的重复材料，冲突在私有工作区阻止 dispatch；新增文件路径不通过 symlink 写出工作区 |
| D19 | 输入按持久接受顺序单独处理，每个 Goal 最多一个理解 job；workflow、input、control 各有独立并发上限 8。显式暂停协调不等待模型回答。停止窗口串行并重新读 head，避免另一个观察 job 与 Stop RPC 的在途状态竞争；尚待实际延迟和故障验证 |
| D20 | typed 路径复用已装配的 `App::decision_model()`，分别判断 query、modify、有限 control 和稳定 target，保留原生分布、usage 与 sanitized error 到产物。没有经过输入评测的直接控制阈值，因此当前所有自然语言提议都经推理校验后提交；没有配置 typed backend 时明确进入推理路径，不伪造概率 |
| D21 | 推理提出完整要求、具体任务修改、明确控制目标与回答/澄清。runtime 验证原输入、接受顺序、owner、scope 和版本，再原子提交。修改仅改变有效要求与受影响任务/下游版本；旧 Execution 保留启动时 Goal/task 版本，旧证据不改标为新版本 |
| D22 | 控制记录按原输入的接受 revision 排序；晚到的旧模型回复不能覆盖之后显式接受的暂停/停止。暂停或停止中保存修改不自动恢复。分支控制绑定实际 task ID，应用到其下游闭包，保留独立分支；恢复分支不恢复暂停的整个 Goal。明确 task 引用不能扩大为整个 Goal 或其他任务控制 |
| D23 | Workspace 准备和 ACP dispatch 分开持久记录。`RequestDispatch` 校验 owner、Goal/task 意图、要求版本和基线后提交；失败不进入 Start。仅确认没有派发过 ACP 的准备失败可自动重试，同一 task 版本最多 3 次；未知 dispatch 不重放，旧尝试继续保留。当前 head 每 task 最多 16 次，长期历史归档/安全恢复尚待完善 |
| D24 | Planning 记录使用的要求版本。旧结果不能安装为新要求的图；保留旧 BlockPlan 的来源。仅当没有任务、新要求已经存在且 Goal 在 Run 时 rearm；同一要求版本的失败不反复调用模型。不清空已有有效安排来响应普通查询或局部修改 |
| D25 | 真实 ACP permission 被转换为 Goal Decision：实际 run/执行、要求/task 版本、原请求引用和 offered options。Human `RespondDecision` 与实际响应派发分别提交；选项、scope、当前执行和暂停状态重新检查，过期响应不能批准 |
| D26 | 当前自动权限匹配仅针对声明为 read/edit/search、全部声明路径位于私有 workspace 的请求，选择实际 AllowOnce。越界、symlink、Execute/Fetch、缺失材料及持久权限不自动批准；硬隔离能力仍依赖 harness/OS 支持，metadata 匹配不是 filesystem sandbox。未批准事项保留为实际 Decision，不以工具标题或模型文字扩大授权 |
| D27 | PermissionResolved 只能支持 controller 已选择该选项，状态使用 Submitted；不据此声称 wire transmission、工具成功或结果验证。未知回应先读实际事件，出现晚到选择证据才协调，不重复发送批准。SDK 的 Lease/Action/Events replay 名称已按当前源码接入，但尚未取得编译证据 |
| D28 | 分支与集成交付的 machine checks 使用有界 recipe：Cargo test/clippy/fmt、npm/pnpm/bun test、实际文件存在/内容检查。命令复用现有进程组清理、有界输出和实际退出记录；没有任意生成 shell。非零退出、超时、未确认结束或检查前后产物变化均不能支持通过。recipe 尚不覆盖所有目标，必需的不支持证据必须阻止交接或完成 |
| D29 | SDK 受控调用持久记录 preparation/input-count/context validation/provider integration、每次实际 provider attempt 及其 outcome；typed 判定也记录实际调用和 usage。保存模型 token 估算、未定价 outcome 与在途 work，不能把估算当发票。回调无法返回提交失败时关闭后续 gate，并拒绝使用未确认保存的模型结果。D34–D36 增加已知 token 估算的冻结预留和 elapsed 限制；统一 request-bill/外部费用协调及验证资源预留仍未实现 |
| D30 | 规划提出非空、合取的 Goal 完成条件和集成检查；最终评估始终读取当前完整 objective、实际集成材料及检查证据，需识别计划中遗漏的原始条件。所有必需条件分别标记 met/unmet/unverified，条件遗漏、invented evidence、原始要求缺失或约束降低不能支持完成。语义质量仍必须经真实评测，不把模型判断本身称为行为证明 |
| D31 | 最终候选出现时触发独立完成评估，复用实际 SDK route，不每轮固定全量 review。并行产物从相同原始 baseline 组合为独立 delivery worktree；拒绝不同 baseline 和冲突，在组合后的准确版本运行整体检查。评估和最终提交再核对产物内容、当前要求、各任务来源、未处理输入及相关未确认执行/计量 work；查看/查询已完成 Goal 不自动重新派发 |
| D32 | 默认 Ready 后自主持久提交完成。显式人工验收保留 AwaitingAcceptance，`AcceptDelivery` 校验要求版本、attempt 和 delivery SHA；模型不能移除已有显式验收。验收响应、完成提交和打开结果是不同事实。旧完成记录留在 immutable operations，新要求开始新的完成 attempt，不能继承旧版完成 |
| D33 | 准备/评估中断、检查未知效果及失败保留原因，不自动重放；同一要求版本的失败不反复调用模型。普通并发输入、事实更新或 lease CAS conflict 只延迟提交，不能被误写成验证失败。安全协调及解锁策略尚需完善；当前 completion blocker 不代替完整预算/分支阻塞/停滞策略 |
| D34 | SDK 新增有实际消费者的 token reservation 回调：从 final-route `TargetTariffSnapshot` 取同一冻结价格/endpoint，按实际 input count 或已知 model input ceiling、受支持的输出 cap，以及所有适用价格 bracket 的最高费率取得保守整数预留。缺失费率、protocol/endpoint 不适用或 token bound 未知时为 None，不能伪造免费。费用来源仍是 configured token estimate；不是 request bill 或全部外部费用硬上限 |
| D35 | 每个 Goal 的 known token exposure = 已记录 token 估算 + 未释放预留。provider attempt admission 与预留在同一 head/receipt CAS 事务内提交；并行和 fallback 不能各自消耗同一余额。plan 先过滤不满足 cap 的 frozen candidate，actual attempt 再校验共享当前余额。未知 usage 保留全部预留，实际 price identity/usage bound 不符或金额超额后保存实际证据并封住新增工作，不把错误支出抹为零 |
| D36 | `SetBudget` 只改 limits，显式 Goal `Control Run` 才清除可解锁的 budget halt；不清空累计消费、未知预留、原暂停/停止事实或旧 completion。elapsed 是从 Goal 创建起的总经过时间，含等待/暂停，并保留已观察最大值防止时钟回退/重启清零。预算 gate 接入模型 work、任务/检查/review admission 和 allow 权限响应；控制协调停止 owned ACP，实际停止另行确认。已成立的完成证据可在 budget halt 后零额外模型调用提交。自然语言预算修改和 interrupted/blocked work 的安全恢复仍未实现 |
| D37 | 三视图使用独立 `bitrouter-tui::goals` 状态机与展示数据，不引入 app/orchestrator/async 依赖，不沿用 native Thread 的 FIFO/steering。复用 Writer 的正常终端历史和 docked footer；app `goal_code` 负责真实本地 Goal RPC、事件 pump、信号和状态投影。S5 源码正在接入，按 spec 的顺序保留现有默认 CLI，S6 在可工作闭环之后切换，不新造临时 `bro goals` 或 legacy alias |
| D38 | 空草稿左右导航；Ctrl-左右提供有草稿时的显式导航。当前 Goal 和 New Goal 草稿分开，每个 Goal 保留独立 editor/阅读状态；右侧所有键位/paste 不进入 composer 或执行控制。Input effect 捕获原 Goal ID，`/task <id>` 是明确引用语法，保留原始文本，理解/意图仍交给 runtime。阅读分支不会 retarget 当前 Goal 或提高调度优先级 |
| D39 | Permission dialog 保留原 offered options/要求版本，无默认 consent，选择后 Enter；人工验收先打开 exact delivery SHA 的卡，再显式确认。新 snapshot 不替换打开的 detail、decision 或 acceptance 身份，backend 仍拒绝过期响应。Ctrl-P/X/R 只在中间向真实服务提交 Goal 意图；右侧完全只读，Escape 和 Ctrl-Q 不停止 Goal |
| D40 | 客户端在发送 mutation 前将原 command/ID/目标/文本保存到 private outbox，文件在 Unix 为 0600，目录为 0700；receipt 必须匹配原 ID、fingerprint 和目标。Storage/transport 失败不能被标为明确拒绝。恢复和未知接收只查询原 receipt；没有可靠 store incarnation 时不自动重放，原意图继续保留。D42 替代初始全局单 mutation slot；完整故障恢复仍待验证 |
| D41 | 右侧 evidence 只读 Goal 私有 hash/长度校验过的 blob，文本 preview 上限 1 MiB，binary/过大内容明确不可预览；没有可操作终端。展示 neutralizes terminal control data，draft 保持原始文本。模型 interpretation 不显示为实际修改；输入结果以 snapshot 内的 `requirements_saved/control_saved/superseded` 等 runtime 字段反馈，dispatch/adoption/verification 保持分离 |
