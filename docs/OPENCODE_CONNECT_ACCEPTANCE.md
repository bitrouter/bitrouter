# OpenCode persistent connection acceptance

Date: 2026-10-31. All native acceptance used temporary homes, XDG directories,
config instances, projects, and dummy credentials. No user's OpenCode
configuration or application profile was changed.

## Contract

`bro connect opencode` creates an independent `provider.bitrouter` named
BitRouter. OpenCode selection ID `bitrouter/automatos` is separate from the exact
gateway request model (`models.automatos.id`) and its picker name
(`models.automatos.name`). Setup leaves other providers, `model`, and
`small_model` unchanged. It stores the gateway key privately in the owned
provider; native `auth.json` entries are unmodified.

The adapter uses the supported custom-provider SDK for Chat Completions,
Responses, or Messages. It inserts no speculative context/output limits, cost,
reasoning, or modality metadata. Desktop and Web configure the local server
instance that reads the config file; editing local files cannot configure a
remote selected server.

## Automated coverage

`apps/bitrouter/src/connect/opencode.rs` contains five focused unit tests for
span-preserving JSONC editing and scoped restoration. They cover comments,
trailing commas, duplicate-key rejection, changed owned-provider conflicts,
later provider additions, later default choices, cleanup of a still-selected
owned default, and rejection of native template markers in all inserted values.
The lightweight extracted harness uses the actual adapter and
shared transaction implementation; its 20 cross-adapter/receipt tests passed.
It is not a full repository build.

`apps/bitrouter/tests/connect_opencode.rs` exercises the actual CLI contract:
explicit instances, existing JSONC, credentials/private modes, repeated setup,
scoped removal after unrelated edits, exact restoration, provider collisions,
provider allowlists, protocol SDK mappings, and XDG/custom-file/custom-directory
discovery. Normal execution does not require an installed OpenCode client.

The ignored native test is opt-in:

```sh
OPENCODE_ACCEPTANCE_BINARY=/path/to/opencode \
OPENCODE_ACCEPTANCE_EVIDENCE=/path/to/evidence \
cargo test -p bitrouter --test connect_opencode \
  native_opencode_streams_and_executes_tool_roundtrip -- --ignored --nocapture
```

That test uses Rust HTTP/SSE fixtures, runs the installed native CLI, and asserts
all three protocols independently. Each protocol sends the exact gateway model
`wire/automatos` with streaming enabled, executes a real native `bash` tool
(`printf BITROUTER_TOOL_OK`), returns its result to the fixture, and streams
`BITROUTER_STREAM_TOOL_ACCEPTED`. It also verifies the configured credential is
sent, an existing unrelated native credential and stale BitRouter `auth.json`
credential survive byte-for-byte, and removal preserves native-added settings
while deleting the owned provider and gateway key.

On macOS OpenCode 1.18.3, this native protocol test passed for all three SDKs
using an extracted runner that calls the actual adapter and shared Receipt.
This validates the adapter/native-client protocol contract. The runner is not
used as evidence of the complete `bro` argument parser or gateway forwarding.

## Native Linux surfaces

Official OpenCode 1.19.5 CLI and Linux Desktop were downloaded from the official
GitHub release. Desktop ran under an isolated X11 display with private HOME/XDG
state. Native Web ran `opencode web` on loopback in the same isolated instance.
The initial config was generated by the real adapter and shared private Receipt,
then copied into that VM's private config instance.

| Surface | Observed acceptance against controlled Rust Chat Completions fixture |
| --- | --- |
| CLI `models bitrouter` | Listed `bitrouter/automatos`. |
| CLI `run --model bitrouter/automatos --format json` | Real bash execution, returned tool result, and streamed final marker. |
| TUI `/models` | Separate BitRouter group and `bitrouter/automatos`; existing OpenCode choices remained. |
| TUI session | Selected entry, executed real bash tool, displayed tool output and final marker. |
| Desktop model picker | Separate BitRouter group with the expected display name. |
| Desktop session | Real native shell tool and streamed final marker; full app relaunch preserved selection and conversation. |
| Local Web model picker/session | Separate BitRouter choice, real shell tool, returned tool result, and final marker. |

The controlled fixture recorded request bodies with `model: wire/automatos`,
distinct from client selector/display `bitrouter/automatos`. Linux UI screenshots
and native/wire JSON evidence are supplied with the review artifacts, prefixed
`opencode-`.

These checks establish native client loading, picker visibility, and tool/stream
compatibility for the tested versions and protocols. Direct fixture evidence is
separate from a complete BitRouter gateway/upstream routing test. It does not
prove production throughput, arbitrary upstream/model compatibility, Windows or
macOS Desktop behavior, or remote-server configuration.

## Source verification

The implementation was checked against the official [custom provider
configuration](https://opencode.ai/docs/providers/#custom-provider), [configuration
locations and JSONC support](https://opencode.ai/docs/config/), [model
selection](https://opencode.ai/docs/models/), the live [configuration
schema](https://opencode.ai/config.json), and [Desktop server
behavior](https://opencode.ai/docs/troubleshooting/). Native isolated
`opencode debug config` confirmed that a custom config directory overrides a
simultaneously set custom config file in the tested client.

## Complete bro CLI and gateway path

The newly compiled real `bro` binary was then tested on the isolated Linux VM,
using a separate config instance and the official OpenCode 1.19.5 CLI. An actual
`bro serve` process listened on loopback port 50401 with a private SQLite fixture
database and control socket. Its `bitrouter/automatos` router selected
`fixture:fixture-target`, backed by the controlled Rust SSE service on port 50400.
This fixture gateway used `skip_auth: true` only on loopback and dummy upstream
credentials.

The real `bro connect opencode` lifecycle passed:

- Dry run left the original JSONC byte-identical.
- Connect retained the native provider/default and wrote the config as 0600.
- Offline status, catalog check, and repeated setup succeeded.
- Native `opencode run --model bitrouter/automatos --format json` streamed a
  tool request through the actual gateway, executed real bash, returned its
  output, and streamed the final marker.
- The upstream wire record contained `model: fixture-target`, proving the
  `bitrouter/automatos` route and forwarding took effect; a subsequent upstream
  request contained the actual `BITROUTER_TOOL_OK` tool result.
- Update changed the picker label and passed a new catalog check while retaining
  later changes to the native provider and a user comment.
- An edited owned model entry caused removal to fail without overwriting it.
- Restoring that owned entry and selecting `bitrouter/automatos` as the config's
  default allowed removal to restore the earlier native default. The later
  native provider change and comment survived; the gateway key and owned
  provider were removed.
- Reconnect followed by removal restored the current native config exactly.

Review artifacts `opencode-actual-bro-lifecycle.json`,
`opencode-actual-bro-native-gateway.jsonl`,
`opencode-actual-bro-gateway-upstream-wire.json`, and
`opencode-actual-bro-restored-config.jsonc` record this separate, complete path.
The direct native-protocol fixture tests additionally cover Responses and
Messages. This forwarded-gateway run specifically covers Chat Completions;
it does not certify gateway conversion for every upstream API/model combination.
