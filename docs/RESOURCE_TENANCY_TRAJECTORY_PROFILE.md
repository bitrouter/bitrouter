# Retained trajectory profile

This additive internal execution profile uses the existing trajectory and Eval ledgers. It adds no management endpoints or fields to the resource-tenancy configuration document. Production dispatch remains gated; M3 receipt qualification is separate.

An admitted retained policy may enable its selected progress guard through the immutable route artifact's explicit `trajectory.enabled` configuration. The selected policy's guard and every selected tier use the retained route envelope and live send authorization. Fixed routes, unused policy references and selected policies without a guard start no trajectory ledger. An unrelated guard does not enable trajectory for another selection.

The profile requires `core` and the explicitly configured tenancy wrapping key. It never uses host trajectory configuration, a generated local correlation key, host evaluator configuration or paid selection. A separate HMAC domain derives correlation from the installation, tenant, configuration revision and fully qualified route and policy references. Creator principal and credential/token identity are excluded from correlation partitions. Principals in the same retained profile can therefore share canonical history; changing that profile creates a different partition. Principal identity remains immutable row provenance.

Retained-content integrity is independent of the reading binary's features. A gateway build without `core` can authenticate and read an inactive guarded revision. It rejects creation, activation, startup with an active guarded revision, and admission of a guarded route with a capability error. Feature removal does not relax encrypted-envelope reconstruction or turn an unsupported inactive draft into a storage failure.

Learning Off retains operational start, route intent, guard and terminal history, and produces no Eval subject, result or outbox. Observe and passive Explore additionally persist the deterministic built-in Generic/Inconclusive operational evaluation. These passive observations, like the generic request recorder and manual import, do not consume `learning.max_evaluations`; that bound applies to initiated evaluator work. There is no new lifetime counter, reset rule, evaluator job or quality score. Selected active experiments remain unsupported in every learning mode.

Selected cost-threshold guards are rejected because the profile does not supply qualified cost evidence. Non-default `retention_days` and `outbox_batch_size` are also rejected. Their defaults remain parameters of the Legacy worker; they do not promise timed deletion or asynchronous publication for tenant rows. This profile performs no automatic owned pruning. Raw provider continuation identifiers are rejected by the trajectory adapter pending a separately qualified continuation/correlation contract.

The existing authority actor owns start and terminal transactions. Start publishes an internal committed-start proof before returning a reply. A missing reply cannot erase the settlement obligation. Only an acknowledged no-transaction or rollback result, together with failed execution, can prove no start occurred. Terminal work uses the execution's existing required-observation cell and pipeline registry. For enabled observations, trajectory terminal state, private built-in Eval admission and delivered outbox commit atomically. The exact built-in evaluator identity is unavailable through manual Eval submission, including to an admitted principal with the same literal authority name. No owned publisher or additional task registry is created. Unexpected owned pending publication rejects startup under the same bootstrap transaction.

Internal bounds are 512 events per episode, 256 canonical ancestor candidates, 4,096 aggregate SQL rows and 32 MiB of serialized SQL cells per composed operation. Logical identity projections are at most 8 KiB, existing trajectory TEXT cells at most 60 KiB, and submitted terminal facts at most 1 MiB. Before committing a start, the actor reserves event slots and complete terminal serialization allowances for every outstanding request. Observe and passive Explore also reserve the complete Eval/outbox envelope, including historical decisions and future routing receipts. Off reserves only its operational closure. Immutable start metadata retains the observation mode and byte allowance; sizing values never become observed evidence. Conservative capacity rejection occurs before provider work and leaves management available. These are bounded work/storage profiles, not disk-space reservations or process RSS guarantees.

Pipeline duration and available token observations are operational evidence. They are not strict receipts, billing authority, proof that a failed provider performed no work, or a process-crash settlement guarantee. Failed required persistence remains fenced and retained through shutdown; unknown transaction cleanup follows the existing authority quarantine policy.
