### Actionable gaps

1. **[P2, A02] Provider conversion is still public AI behavior.** `crates/bitrouter-ai/src/types.rs:718`, `ToolResultOutput::to_provider_string`, projects canonical output onto string-only provider wires: it discards media/file references, collapses error variants and supplies provider-facing denial text. `GenerationParams::extras_for_protocol` at `:1529` and `extra_value_for_protocol` at `:1545` choose outbound fields by source/target protocol and server-default precedence. These are semantic adaptation, not serde or intrinsic field validation. Actual production consumers are gateway renderers: `apps/bitrouter/src/gateway/model/protocol/chat_completions.rs:1394`, `apps/bitrouter/src/gateway/model/protocol/messages.rs:1412`, `apps/bitrouter/src/gateway/model/protocol/responses.rs:2397`; no SDK or matcher consumer of these helpers was found. Move the implementations to application-owned model/codec helpers, preserve behavior at existing callers, and retain only the necessary data representation in AI. Also review `from_untyped_value` at `types.rs:697` as part of that extraction. A light dependency graph does not close this gap.

2. **[P2, A02] Host-policy admission is still implemented in AI.** `crates/bitrouter-ai/src/core/protocol.rs:602`, `Limits::within`, compares requested execution allowances against host policy and returns admission errors; `Capabilities::negotiate` calls it at `:547`. Production admission calls occur in `apps/bitrouter/src/core/session.rs:4620` and `apps/bitrouter/src/storage/checkpoint/validation.rs:66`. These are application policy decisions, explicitly excluded by the plan's public-contract rule. Move host-policy comparison/admission into application helpers; retain wire data and intrinsic `Limits::validate`/identifier validation in AI. This finding concerns the current A02 API surface, not a claim to have inventoried the old orchestrator package.

Both findings were independently reproduced by a separate read-only source reviewer. No fixes were attempted during the source freeze.

- **AI dependency/source boundary:** `crates/bitrouter-ai/Cargo.toml:12` declares only empty defaults, `testing`, and optional `schema`; dependencies are serde, serde_json, thiserror and optional schemars. No application/SDK, HTTP, async runtime, DB, terminal or OTel dependency is declared. Its current public module declarations and foreign dependency manifest contain no live provider transport, credential store, cancellation/scheduler handle or database transaction. Filesystem/environment hits are schema tests, not production contract code. This is manifest/API inspection, not a newly resolved or built all-features graph.
- **AI semantic boundary:** conversion admission is in gateway `model/conversion.rs`; protocol/history handling is in gateway `model/protocol/`, with shared internal history helpers in `model/history.rs` gated by `core || harness`. Conversion reports, event data and bounded callback signatures are legitimate public data. Findings 1–2 prevent a full A02 source sign-off. No claim is made that every helper or every wire round trip is behaviorally verified.

The regex matcher consumes request-check `Input`/`Decision`/`Callback`. Catalog artifact definitions and observation schema have the concrete consumers described in the map. Internal TypeSafe decisions and caller contexts were not published merely to satisfy a directory split.
- **SDK dependency/ownership boundary:** `crates/bitrouter-sdk/Cargo.toml:15` has empty defaults and optional client-only `core`; no application, provider-auth, ORM, server or terminal normal dependency. Axum/hyper server facilities appear only in dev-dependencies. New SDK code contains HTTP/service framing and public error handling, not local filesystem/profile discovery, service bootstrap or provider execution. SDK Tokio is transport support, not service ownership.
- **Credentials/authority:** gateway, control and harness each construct their own client from explicit endpoint/credential arguments. Gateway `gateway.rs:79`, control `control.rs:58`, harness `harness.rs:56`; redirects and transport retries are disabled (`transport.rs:81`, `control.rs:75`). Proxy discovery is explicit opt-in. #### Feature notation
